# NQX-S1: процессор для NautilusQuant, краткое руководство

Этот раздел репозитория содержит полный проект микросхемы, которая
аппаратно выполняет сжатие KV-кэша NautilusQuant. В нём всё, что нужно для
заказа на фабрике: от эталонной модели до файла топологии (GDSII),
прошедшего проверки.

## Что это за чип

- На вход поступает вектор из 128 чисел int16 (256 байт). На выходе
  получается пакет из 70 байт: 3-битный радиус и 3-битный угол на каждую
  пару плюс по одному корректирующему биту. Чип выполняет и обратную
  операцию.
- Вращение по золотому углу генерируется **без таблицы углов**. Углы
  (k+1)·2π/φ² нарастают равномерно, поэтому их даёт 32-битный фазовый
  аккумулятор с константами `0x61C88647` и `0x9E3779B9` (это «золотые»
  константы хеширования Кнута). Сам поворот выполняет конвейер CORDIC на
  сдвигах и сложениях, без умножителей. В `nqx-core` для того же нужна
  таблица 1,9 КБ, случайному вращению нужна матрица 32 КБ, а здесь хватает
  трёх регистров.
- Приращения углов программируются. Это позволит на готовом кремнии
  опробовать исправление алгоритма (см. ниже) без перевыпуска чипа.
- Интерфейс: 8 бит на вход и 8 бит на выход с асинхронным «рукопожатием».
  Подключается к любому микроконтроллеру, например Raspberry Pi Pico.

## Что важно знать об алгоритме (найдено при переносе в железо)

Подробности в [`spec/11_algorithm_findings.md`](spec/11_algorithm_findings.md).

1. **Третий слой вращения ничего не делает.** Его угол равен ровно
   2π·(k+1), то есть целому числу оборотов. В чипе этот слой по умолчанию
   пропускается, результат от этого не меняется.
2. **Углы второго слоя равны углам первого с обратным знаком**
   (1/φ + 1/φ² = 1).
3. **Главный выигрыш даёт квантователь, а не φ.** Новые правила
   квантования в чипе снижают ошибку восстановления более чем вдвое
   (0,316 → 0,147) при тех же 4 битах на значение. Это: диапазон радиуса
   по каждому вектору, круговой код угла и использование бита остатка при
   декодировании.
4. **Честное сравнение.** Золотой угол лучше, чем отсутствие вращения
   (−9 % ошибки), но хуже случайного вращения (+17 % ошибки) на
   синтетических данных с выбросами. Реальное преимущество золотого угла в
   железе другое: нулевая память под вращение и полная детерминированность.
   Эти выводы стоит проверить на настоящих KV-кэшах Llama/Qwen.

| Тестовые векторы для кремния | `vectors/`: 91 транзакция, проверены на RTL, на уровне выводов и на нетлисте после трассировки |
| Топология под IHP SG13G2 (130 нм, Германия) | Полный кристалл: 31 контактная площадка, seal ring, заполнение металлом. Подпись пройдена: DRC по полному набору правил IHP — 0, плотность и антенны — 0, LVS совпадает, время сходится на трёх углах (+1,08 нс на медленном), нетлист после трассировки проходит эталонные векторы. Результаты в [`spec/06`](spec/06_physical_design.md), файлы в `tapeout/ihp-sg13g2/` |
| Топология под GF180MCU (wafer.space) | Проект на официальном шаблоне wafer.space. GDS и их precheck собирает GitHub Actions |
| Документация | 12 документов в `spec/`: даташит, архитектура, система команд, численный анализ, верификация, физический дизайн, тестирование, пакет для фабрики, обзор конкурентов, запуск |

**Порядок действий для wafer.space:**

1. Запустите в GitHub: Actions → `nqx-silicon` → Run workflow (с галочкой
   «gds»). Будут собраны GDS для двух размеров слота и выполнен официальный
   precheck wafer.space.
2. Выберите слот, который прошёл precheck: 0,5×0,5 дешевле, 0,5×1 надёжнее
   по плотности.
3. Купите слот на wafer.space / Crowd Supply до 09.12.2026. При желании
   добавьте опцию chip-on-board, чтобы сразу получить кристаллы на плате.
4. Загрузите `final/gds/chip_top.gds` из артефактов CI до 16.12.2026.
5. Когда придут чипы: прошейте Pico и запустите тестовые векторы
   ([`spec/10_bringup.md`](spec/10_bringup.md)).

## Что стоит сделать до заказа

- Выбрать фабрику и бюджет. Этот выбор за вами.
- Запустить сборку в CI (пункт 1 выше) и убедиться, что precheck
  wafer.space зелёный.
- По возможности проверить выводы про квантователь на реальных KV-данных
  (`validate_real_kv.py`).

## Ограничения, о которых нужно знать

- Это **тестовый чип**, а не ускоритель для LLM. Скорость ограничена
  8-битной шиной: около 69 тыс. векторов в секунду при идеальном хосте и
  50 МГц. Путь к производительному чипу описан в
  [`spec/02_architecture.md`](spec/02_architecture.md) §9.
- Характеристики на кремнии ещё не измерены. Цифры потребления и частоты
  получены статическим анализом.
- Сканирующих цепочек (scan DFT) нет. Тестирование функциональное, через
  команды; для MPW-чипов это стандарт.
